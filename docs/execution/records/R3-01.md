## Evidence brief before implementation

- Current behavior:
  - Language server provides standard LSP endpoints (completion, hover, definition, diagnostics) through `GrailsTextDocumentService` and `GrailsWorkspaceService`.
  - Custom protocol in `GrailsLanguageClient` only notifies `projectsDiscovered`, `projectUpdated`, and `projectPatched`.
  - There is no unified, typed analysis operation boundary exposing `project.capabilities`, `symbols.search`, `symbols.explain`, and `project.diagnostics` with envelope metadata (schemaVersion, analysisRevision, freshness, completeness, per-item resolution/evidence).
  - No schemas exist defining structured query envelopes for tools or agent consumers.
- Failure/missing behavior and smallest reproducer:
  - Missing operation contracts: Agent readers and tool consumers cannot perform bounded reads with explicit freshness (`current`/`stale`/`unavailable`) and completeness (`complete`/`partial`/`unavailable`).
  - Missing boundary validation: Need strict parameter validation, count and byte budget caps, and cursor expiration handling.
  - Risk of second index: Without a shared analysis operation service, an agent layer might create a competing external index violating `INV-TOOL-001`.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-TOOL-001`: Editor and agent adapters must use the same typed analysis operations and scoped revisions; no independent competing index.
  - `INV-TOOL-003`: Inputs, paths, pagination, result size, and permissions must be validated at the operation boundary.
  - `INV-STATE-004`: Publication correctness; candidate state published only when validated.
  - `INV-STATE-006`: Fail-safe defaults; invalid/unknown inputs must never crash; return explicit error/unavailable.
  - `INV-DISC-003`: Results retain origin, derivation, scope, and limitations.
- Unknowns and how this task will resolve them:
  - Envelope schema: Established in `shared/schemas/analysis-operations.json` and mirrored in `client/src/shared/protocol/analysis.ts` and `server/src/main/groovy/kingsk/grails/lsp/core/analysis/`.
  - Data sources: Operations directly read existing `ProjectContextImpl` snapshots (`SnapshotManager`), `FileContentTracker` (unsaved buffers), `DiscoveryService`, `DeclarationDiscoveryService`, capability adapters, and `CompatibilityMatrix`.

## Implementation decision

- Intended observable result; non-goals:
  - Observable result: Shared JSON schema `shared/schemas/analysis-operations.json`, TypeScript definitions `client/src/shared/protocol/analysis.ts`, and Groovy operational service `AnalysisOperationService` handling the 4 operations with full envelope semantics, count/byte caps, cursor pagination, and Spock test suite `SharedAnalysisOperationsSpec`.
  - Non-goals: VS Code tool registration (owned by R3-02), mutations, application execution, or file editing.
- Files/owners to change:
  - `shared/schemas/analysis-operations.json`: Canonical JSON Schema.
  - `client/src/shared/protocol/analysis.ts`: Client TypeScript interfaces.
  - Server classes under `kingsk.grails.lsp.core.analysis.*`:
    - `AnalysisOperationService.groovy`: Core dispatcher and coordinator.
    - `AnalysisFreshness.groovy`: Enum (`CURRENT`, `STALE`, `UNAVAILABLE`).
    - `AnalysisCompleteness.groovy`: Enum (`COMPLETE`, `PARTIAL`, `UNAVAILABLE`).
    - `AnalysisResolutionKind.groovy`: Enum (`DECLARATION_BACKED`, `FRAMEWORK_DERIVED`, `RUNTIME_OBSERVED`, `HEURISTIC`, `UNRESOLVED`).
    - `AnalysisEvidence.groovy`: Locators, artifact coordinates/fingerprints, adapter rules.
    - `AnalysisSymbolItem.groovy`: Symbol item with provenance and evidence.
    - `AnalysisDiagnosticItem.groovy`: Diagnostic item.
    - Envelopes and operation requests/responses for `project.capabilities`, `symbols.search`, `symbols.explain`, `project.diagnostics`.
  - `server/src/test/groovy/kingsk/grails/lsp/analysis/SharedAnalysisOperationsSpec.groovy`: Verification test suite.
- Input revision, candidate state, commit/publication and cancellation behavior:
  - Operations capture the current snapshot and unsaved open buffers from `FileContentTracker`.
  - Operations accept cancellation token; check thread interruption.
- Cache/resource impact, limits and invalidation:
  - Stateless execution; counts capped (e.g. max 50 default, max 200 hard limit); bytes capped (e.g. max 64 KiB default, max 256 KiB hard limit).
- Alternatives considered and evidence for the smallest sufficient change:
  - Building a second SQLite or Lucene index rejected: directly violates `INV-TOOL-001`. Reading `ProjectIndex` and `FileContentTracker` directly reuses validated memory state.
- Contract conflict/ADR update, if any: None.
