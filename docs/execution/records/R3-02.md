## Evidence brief before implementation

- Current behavior:
  - R3-01 defined shared typed analysis operations in `AnalysisOperationService.groovy` and canonical schema / TypeScript types (`analysis-operations.json`, `analysis.ts`).
  - Currently, these operations are only callable via internal Groovy API on the server.
  - The language server does not expose these 4 operations via `workspace/executeCommand`.
  - The client extension has no service or language model tool registrations (`vscode.lm.registerTool`), nor editor commands for invoking analysis operations without an LLM.
- Failure/missing behavior and smallest reproducer:
  - Missing agent tools: VS Code chat / agent participants have no registered language model tools for inspecting project capabilities, searching symbols, explaining symbols, or viewing diagnostics.
  - Missing editor fallback: Deterministic IDE commands for analysis queries are not registered.
  - Missing boundary guards: Need client-side trust checks (`vscode.workspace.isTrusted`) and scope checks (`vscode.workspace.getWorkspaceFolder`) before sending read operations to LSP server.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-OWN-003`: No `ServiceContainer` inside services. Client services receive dependencies via constructor injection only.
  - `INV-TOOL-001`: Editor and agent adapters use the same typed analysis operations and scoped revisions; no independent competing index.
  - `INV-TOOL-002`: Previews/checks/application have explicit input identities; reads never execute builds or applications.
  - `INV-TOOL-003`: Inputs, paths, pagination, result size and permissions are validated at the operation boundary.
- Unknowns and how this task will resolve them:
  - Tool registration mechanism: VS Code `languageModelTools` contribution in `package.json` plus `vscode.lm.registerTool` in client `AnalysisToolService`.
  - Editor workflow: `AnalysisCommands` and UseCases providing deterministic command invocation (`grails.analysis.*`).

## Implementation decision

- Intended observable result; non-goals:
  - Observable result:
    1. Four Language Model Tools registered in VS Code: `grails_project_capabilities`, `grails_symbols_search`, `grails_symbols_explain`, `grails_project_diagnostics`.
    2. Server `executeCommand` handling `grails.analysis.*` commands via `GrailsWorkspaceService.groovy`.
    3. Client `AnalysisToolService` implementing `Disposable`, constructor-injected via `ServiceContainer`, with trust/scope validation and error handling.
    4. Deterministic editor commands and UseCases callable without an LLM.
    5. Full automated test suites on both server (`WorkspaceAnalysisOperationsSpec`) and client (`analysisToolService.unit.test.ts`).
  - Non-goals: MCP transport (owned by R3-04), mutations/refactoring previews (owned by R5).
