## Evidence brief before implementation

- Current behavior:
  - Language features (completion, hover, definition, references, inlay hints, signature help, rename) had divergent symbol and type resolution routines across different providers.
  - Several providers implemented bespoke or incomplete AST traversal/inference rather than delegating to the unified compiler context (`RequestContext`, `SnapshotManager`, `GrailsASTVisitor`, `GrailsASTHelper`, `MemberExtractor`).
  - Pre-existing failures and regressions observed:
    1. In `GroovyCompletionProviderSpec`, member access completions on `localVar[0].` failed to resolve byte-code methods (such as `charAt`).
    2. In `GrailsObjectExpressionCompletionSpec`, domain relationship completions (`person.books.`) failed because static AST fields (`hasMany`) were not resolved from shallow type references to the declaring AST `ClassNode`.
    3. In `GrailsObjectExpressionCompletionSpec`, non-Grails static completions on `Person.` included instance DGM methods (`count`) due to unconditional `addMemberCompletions` before static access discrimination.
    4. In `GrailsObjectExpressionCompletionSpec`, controller render completions failed because cursor positions past line length were misclassified as prefix matches (`render`) rather than empty whitespace prefixes.
    5. In `GrailsReferenceProviderSpec` and `GrailsRenameProviderSpec`, `(definitionNode as PropertyNode).field` threw `GroovyCastException` when `definitionNode` was a `VariableExpression`.
    6. In `GrailsDefinitionProviderSpec`, local variable definition tests failed when `getDefinition` returned `node.accessedVariable` instead of the declared `originType`.
- Failure/missing behavior and smallest reproducer:
  - Running `./gradlew test -x jacocoTestReport` showed failures in `GroovyCompletionProviderSpec`, `GrailsObjectExpressionCompletionSpec`, `GrailsDefinitionProviderSpec`, `GrailsReferenceProviderSpec`, and `GrailsRenameProviderSpec`.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-ID-003`: `SymbolInfo.id` is durable only within a snapshot.
  - `INV-ID-004`: AST node identity (`ClassNode`, `MethodNode`) is valid only within a proven retained generation/request lease; never cached across generations.
  - `INV-ID-005`: Line/column positions bound to document/analysis revision; map or revalidate when current text differs; never reuse unqualified old ranges.
  - `INV-KEY-003`: SymbolInfo IDs are snapshot-scoped.
  - `INV-KEY-005`: Provider state is request-scoped; providers hold no state between requests.
  - `INV-STATE-004`: No partial visibility; providers never observe half-built ASTs or partially updated indexes.
- Unknowns and how this task resolved them:
  - Unified AST type resolution in `GrailsASTHelper.getTypeOfNode` by delegating to `tryToResolveOriginalClassNode` against `visitor.classNodes` to resolve full AST definitions (containing static fields like `hasMany`, `hasOne`, `belongsTo`) from shallow compiler references.
  - Separated static and instance completion pathways in `PropertyExpressionStrategy`.
  - Added safe `PropertyNode` type guards in `GrailsASTHelper.getReferences`.
  - Reinstated standard `originType` resolution for `VariableExpression` in `GrailsASTHelper.getDefinition`.
  - Adjusted `CompletionProcessor.extractPrefix` to handle cursor positions beyond line boundaries.
