## Evidence brief before implementation

- Current behavior:
  - While symbol search, definitions, and completions existed, there was no structured, bidirectional graph model of Grails framework relationships across domain entities (associations, inheritance), controllers (action conventions, view/template rendering, dynamic render calls), services (property and constructor injection), TagLibs (custom tags), and UrlMappings (declarative routes and wildcard dynamic routes).
  - Agent tools and IDE views lacked a unified queryable operation to traverse relationships with depth limits, cycle handling, directionality filtering, pagination, and byte budgets.
  - Previous index snapshot models held symbol indices but had no compact relationship fact storage or target-URI inverted indices.
- Failure/missing behavior and smallest reproducer:
  - Attempting to inspect or navigate relationships between a controller and its rendered views or injected services required ad-hoc text search or unevidenced heuristic string guessing.
  - No operation or tool existed for `grails_relationships` in either LSP workspace command, client `AnalysisToolService`, or MCP server.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-DISC-001`: Framework relationships must be grounded in actual AST/conventions/metadata, not synthetic speculation.
  - `INV-DISC-003`: Dynamic unknowns (e.g. dynamic view names or wildcard controller mappings) must be explicitly marked as unresolved/dynamic rather than silently dropped or falsely resolved.
  - `INV-OWN-004`: Eviction of a document or project cleans up all owned index facts and inbound/outbound relationship edges.
  - `INV-OWN-005`: No AST node objects (`ClassNode`, `MethodNode`, etc.) are retained across snapshot/generation boundaries; facts are serialized as immutable, compact DTOs.
  - `INV-TOOL-001/003`: Agent/MCP tools use bounded operations with pagination, max depth, cycle protection, and strict argument validation.
- Unknowns and how this task resolved them:
  - Implemented `GrailsRelationshipExtractor` to walk AST nodes deterministically (avoiding double-dispatch Groovy compilation pitfalls) to extract `DOMAIN_ASSOCIATION`, `SERVICE_INJECTION`, `CONTROLLER_ACTION_ROUTE`, `VIEW_RENDER`, `TAGLIB_TAG`, and `CONFIG_BINDING`.
  - Stored relationship facts in `IndexSnapshot` as immutable maps indexed by source URI and target URI.
  - Integrated with `IndexManager` CAS rebuild and eviction loops, ensuring file deletion removes both outbound and inbound edges.
  - Implemented `AnalysisOperationService.executeRelationships` supporting BFS traversal with cycle detection, max depth (default 1, max 5), max edge cap (2000), direction filtering (`outbound`, `inbound`, `both`), type filtering, and cursor-based pagination.
  - Exposed via LSP command `grails.analysis.relationships`, client use case `GetRelationshipsUseCase`, VS Code language model tool `grails_relationships`, and MCP tool `grails_relationships`.

## Implementation decision

- Intended observable result; non-goals:
  - Observable result:
    1. Fast, deterministic relationship queries across all standard Grails relationship kinds.
    2. Dynamic/wildcard route and view targets explicitly represented with `resolution: "unresolved"` and `kind: "unknown"`.
    3. Document deletion immediately evicts all associated relationship edges from the snapshot index.
    4. Client command, VS Code agent tool, and MCP tool all provide access to identical bounded relationship results.
  - Non-goals:
    - GSP embedded language editing (handled in R4-03).
    - Configuration and i18n metadata analysis (handled in R4-04).
- Files/owners changed:
  - Shared schemas: `shared/schemas/analysis-operations.json` (added relationship schemas and request/response contracts).
  - Client protocol: `client/src/shared/protocol/analysis.ts` (added TS relationship types).
  - Server model:
    - `kingsk.grails.lsp.core.analysis.RelationshipType.groovy` (enum of relationship types).
    - `kingsk.grails.lsp.core.analysis.RelationshipEndpoint.groovy` (endpoint model with resolution state).
    - `kingsk.grails.lsp.core.analysis.GrailsRelationshipItem.groovy` (immutable relationship item).
    - `kingsk.grails.lsp.core.analysis.GrailsRelationshipsRequest.groovy` & `GrailsRelationshipsResponse.groovy` (request/response DTOs).
  - Server extraction & index:
    - `kingsk.grails.lsp.index.GrailsRelationshipExtractor.groovy` (relationship extraction engine).
    - `kingsk.grails.lsp.index.IndexSnapshot.groovy` (relationship indexing and fast lookup).
    - `kingsk.grails.lsp.index.IndexBuilder.groovy` (builder hook).
    - `kingsk.grails.lsp.index.IndexManager.groovy` (CAS update and eviction lifecycle).
  - Server operations:
    - `kingsk.grails.lsp.core.analysis.AnalysisOperationService.groovy` (BFS traversal, pagination, filtering).
    - `kingsk.grails.lsp.services.GrailsWorkspaceService.groovy` (LSP command dispatch).
  - Client services & MCP:
    - `client/src/services/analysis/AnalysisToolService.ts` (client tool method and LM tool registration).
    - `client/src/ui/commands/AnalysisCommands.ts` (use case and command registration).
    - `client/src/mcp/GrailsMcpServer.ts` (MCP tool registration and schema validation).
- Input revision, candidate state, commit/publication and cancellation behavior:
  - Relationship queries inspect active `VersionedSnapshot` and reflect `analysisRevision`. CancellationToken checks protect traversal.
- Cache/resource impact, limits and invalidation:
  - Traversal bounded to 2000 edges and depth <= 5. No AST nodes retained in relationship items. Eviction completely removes edges.
