## Evidence brief before implementation

- Current behavior:
  - Configuration support was limited to basic YAML completion heuristics (`GrailsYamlIntelligenceProvider`) without support for `.properties` or `.json` configuration formats.
  - No parsing or extraction of environment override blocks (`environments.development.*`, `environments.test.*`).
  - No placeholder extraction (`${SERVER_PORT:8080}`) or definition jumping to referenced properties.
  - No dynamic discovery of plugin configuration properties from `META-INF/spring-configuration-metadata.json` in installed dependency JARs; hardcoded property lists risked missing valid plugin configurations or flagging them as invalid.
  - No i18n cross-locale message resolution or linking between Groovy/GSP `g:message(code: '...')` calls and `grails-app/i18n/*.properties`.
  - Sensitive plaintext secrets were exposed directly in hovers without masking.
- Failure/missing behavior and smallest reproducer:
  - Opening `application.properties` or `application.json` provided no configuration completions or hovers.
  - Hovering on `dataSource.password` in `application.yml` revealed the plaintext password.
  - Adding a custom plugin with `spring-configuration-metadata.json` did not make its configuration properties discoverable.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-DISC-001`: Grounding in installed artifacts — configuration metadata must be parsed dynamically from project dependencies and classpath JARs, not static hardcoded inventories.
  - `INV-DISC-003`: Project isolation — configuration metadata registries and i18n indexes are owned per project by `ProjectContextImpl` without default-project leakage.
  - `INV-EDIT-001`: Accurate document coordinate mappings for placeholders and configuration values.
- Unknowns and how this task resolved them:
  - Multi-locale aggregation: `I18nIntelligenceService` indexes all matching `messages*.properties` per project, aggregating translations by locale key (`default`, `es`, `fr`, etc.) for rich hover documentation and multi-file definition navigation.
  - False-invalid diagnostic prevention: The configuration analyzer verifies syntax errors and warns on plaintext secrets, but explicitly suppresses unknown-property diagnostics when metadata is incomplete, avoiding false-positive errors on user-defined configuration sections.

## Implementation decision

- Intended observable result; non-goals:
  - Server models and services:
    - `ConfigurationPropertyMeta.groovy`: Holds metadata facts (type, description, defaultValue, deprecation, sourceArtifact).
    - `ConfigurationNode.groovy`: AST representation of configuration facts tracking dotted path, segment, environment, source URI, ranges, placeholders, and sensitive flag.
    - `ConfigurationParser.groovy`: Multi-format parser for YAML (nested maps, dotted keys, lists/arrays, `environments` blocks), Properties (`key=value`), and JSON. Extracts `${VAR:default}` placeholders, detects sensitive keys, and provides `maskIfSensitive`.
    - `ConfigurationMetadataRegistry.groovy`: Thread-safe registry parsing `spring-configuration-metadata.json` and `additional-spring-configuration-metadata.json` dynamically from JSON strings, JAR files, and classpath dependencies. Purges metadata cleanly when dependencies are removed.
    - `I18nEntry.groovy` & `I18nIntelligenceService.groovy`: Indexes `grails-app/i18n/*.properties`, provides multi-locale hover, multi-location definition jumps, and completion items.
    - `GrailsConfigurationIntelligenceProvider.groovy`: Document provider handling completion, hover (with `******` secret masking and multi-locale i18n preview), definition jumps (for placeholders and message codes), and syntax/plaintext diagnostics.
    - `GrailsYamlIntelligenceProvider.groovy`: Extends `GrailsConfigurationIntelligenceProvider` for backwards compatibility.
    - `ProjectContextImpl.groovy`: Owns `ConfigurationMetadataRegistry` and `I18nIntelligenceService` per project lifecycle.
  - Client services and tests:
    - `clientConfig.ts`: Added `yaml` and `json` to `documentSelector` and registered watchers for `**/*.{groovy,gsp,properties,yml,yaml,json}` and `**/application*.{yml,yaml,properties,json}`.
    - `configIntelligence.unit.test.ts`: Client unit tests verifying document selectors and file watchers.
    - `ConfigurationAndI18nIntelligenceSpec.groovy`: Comprehensive server Spock specification covering YAML/JSON/Properties parsing, placeholder navigation, i18n multi-locale hover/definitions, dynamic metadata registration/removal, false-invalid avoidance, and secret masking.
