## Evidence brief before implementation

- Current behavior:
  - `GrailsTreeExplorer.ts` had several exploration handlers commented out (`ConfigRoot`, `ViewsRoot`, `AssetsRoot`, `RoutesRoot`, `SrcRoot`, `TestsRoot`, `DependenciesRoot`, `SourceDir`, `TestDir`, `ViewsFolder`, `AssetsFolder`), returning empty arrays when expanded.
  - `getArtifactFiles` invoked `getPackagesWithFiles`, which performed eager recursive filesystem traversals through the entire directory subtree upon opening an artifact folder, violating `INV-PERF-002`.
  - Tree items lacked project-scoped identifiers (`id`), risking state collisions in multi-module workspaces with shared directory structures (`INV-OWN-003/004`).
  - Generated sources under `build/generated` were not discovered or labeled, with no read-only designation.
  - Large directories had no defensive bounds, risking extension host lockups on deeply nested or massive folders.
  - Screen reader accessibility labels were missing on tree nodes.
- Failure/missing behavior and smallest reproducer:
  - Opening a multi-module workspace with subprojects caused ambiguous node identity.
  - Expanding "Controllers" eagerly enumerated all subdirectories recursively instead of lazily expanding on demand.
  - Generated source files had no visual distinction or read-only indicators.
  - Empty directories had no clear `(Empty)` representation.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-DISC-001`: Source set and Gradle model alignment — exploration follows Gradle roots/source sets and Grails conventions rather than hardcoded directory depths.
  - `INV-OWN-003/004`: Stable, scoped identity — tree node IDs scoped to `${project.rootPath}::${kind}::${resourcePath}` to guarantee durable cross-module separation.
  - `INV-PERF-002`: Lazy resolution and bounded work — children resolve strictly upon node expansion, capped at `MAX_DIRECTORY_ITEMS = 300` with truncation indicators; no full-tree recursion at startup or activation.
- Unknowns and how this task resolved them:
  - Package compacting: Implemented `compactPackagePath` to compact linear single-child chains (e.g. `com/example/app`) into a single dot-separated label (`com.example.app`) lazily without deep sibling traversal.
  - Generated source representation: Detected `build/generated/sources` and `build/generated`, assigning `TreeItemKind.GeneratedRoot`, `GeneratedDir`, and `GeneratedFile` with explicit `description = "(generated, read-only)"` and accessible announcements.

## Implementation decision

- Intended observable result; non-goals:
  - Client tree model and explorer:
    - `TreeItemKind.ts`: Added `GeneratedRoot`, `GeneratedDir`, `GeneratedFile`, `Empty`, and `Loading` enum variants.
    - `IconProvider.ts`: Registered icons for `GeneratedRoot` (`file-binary`), `GeneratedDir` (`folder`), `GeneratedFile` (`file-code`), `Empty` (`info`), and `Loading` (`loading~spin`).
    - `GrailsTreeItem.ts`:
      - Assigned deterministic project-scoped `id` (`${project.rootPath ?? "global"}::${kind}::${resourcePath ?? label}`).
      - Assigned screen-reader accessible `accessibilityInformation.label` detailing name, kind, generated/read-only status, and project name.
      - Added `description = "(generated, read-only)"` for generated source nodes.
    - `GrailsTreeExplorer.ts`:
      - Rewrote `getChildren(element)` switch handling all sections lazily (`ProjectRoot`, `GrailsAppRoot`, `GrailsArtifactFolders`, `ConfigRoot`, `ConfFolder`, `I18nRoot`, `ViewsRoot`, `ViewsFolder`, `AssetsRoot`, `AssetsFolder`, `RoutesRoot`, `SrcRoot`, `SourceDir`, `TestsRoot`, `TestDir`, `GeneratedRoot`, `GeneratedDir`, `InitRoot`, `DependenciesRoot`, `DEPENDENCY_CATEGORY`).
      - Implemented `readDirectorySafely` with `MAX_DIRECTORY_ITEMS = 300`, sorting, defensive error handling, and truncation node (`... and N more items`).
      - Implemented single-chain package compacting (`compactPackagePath`) for artifact, source, and generated directories.
      - Implemented artifact type matching (`matchesArtifactType`) separating controllers, services, domains, taglibs, interceptors, jobs, and commands according to Grails conventions.
      - Implemented empty state handling returning `(Empty)` node (`TreeItemKind.Empty`) on empty directories.
      - Implemented recoverable error state returning `(Folder not found)` or `Error: ...` on filesystem errors.
      - Cleaned up event subscriptions and disposables in `dispose()`.
    - `treeExplorer.unit.test.ts`: Added 7 comprehensive unit tests verifying multi-module scoped identities, lazy resolution, generated source labels, package compacting, empty state, missing directory handling, and 300-item truncation.
