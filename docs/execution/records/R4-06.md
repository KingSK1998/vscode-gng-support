## Evidence brief before implementation

- Current behavior:
  - `GrailsTaskCommands.ts` hardcodes `projects[0]` rather than resolving the active project from editor context or user selection.
  - `GrailsTestService.ts` contains prototype mockup logic (`Math.random() > 0.1` and "Test failed intentionally in prototype") in `runTests` rather than executing actual tests via Gradle.
  - `DebugService.ts` uses an arbitrary `setTimeout(8000)` wait and hardcoded port 5005 without checking if the port is free or detecting port conflicts, and does not check for the Java debugger extension or workspace trust.
  - `LegacyCommands.ts` hardcodes `./gradlew` (which fails on Windows cmd/pwsh) and executes outdated Grails commands (`run-app`, `test-app`).
  - Neither `GradleService`, `DebugService`, nor `GrailsTestService` checks `vscode.workspace.isTrusted`.
  - Process termination and cancellation are not tracked: child processes spawned during tasks/debug/tests are not killed on token cancellation or service disposal.
  - Missing Java, wrapper missing/failure, and port conflicts do not provide actionable, user-friendly diagnostics.
- Failure/missing behavior and smallest reproducer:
  - In an untrusted workspace, tasks or tests can be triggered without trust verification.
  - Running a test suite with 0 tests reports a random failure or arbitrary delay instead of explicit `no-tests` handling.
  - Port 5005 or 8080 conflicts fail silently or with opaque stack traces instead of actionable instructions.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-OWN-003`: No ServiceContainer inside services; constructor injection only.
  - `INV-TOOL-002`: Previews/checks/application have explicit input identities, trust boundaries, and report honest results.
  - `INV-PERF-002`: Process admission, bounded output, cancellation and disposal cleanup.
- Unknowns and how this task will resolve them:
  - Clean execution engine fallback: `GradleService` will support wrapper-based process execution with stream filtering, cancellation, and port-conflict detection.
  - Port availability checking: asynchronous socket probe detects port occupation before launch and output stream scanning catches runtime bind failures.

## Implementation report

- Implemented features:
  - **GradleService execution engine**:
    - Added workspace trust verification (`vscode.workspace.isTrusted`). Untrusted workspaces reject task execution with `WORKSPACE_UNTRUSTED` error code and actionable guidance.
    - Added Java environment resolution checking `grails.javaHome`, `JAVA_HOME`, and system PATH. Missing Java yields `JAVA_MISSING` failure code.
    - Added platform-aware Gradle wrapper resolution (`gradlew.bat`/`gradlew.cmd`/`gradlew` on Windows, `gradlew` on POSIX).
    - Added port availability checking via dynamic TCP server socket probe and stream scanning for bind errors (`PORT_CONFLICT`), providing clear advice to terminate existing processes or configure alternate ports.
    - Added process tracking in `runningProcesses` map, cancellation token support (`SIGTERM` with `SIGKILL` fallback), cancellation of previous instances on restart, and thorough process cleanup upon `dispose()`.
    - Added Gradle test outcome parsing distinguishing pass, fail, skip, and `noTests`.
  - **GrailsTestService real test execution**:
    - Injected `GradleService` via constructor injection (`INV-OWN-003`).
    - Enforced workspace trust check.
    - Handled `no-tests` case cleanly without artificial pass or fail.
    - Formulated `--tests` filter arguments per enclosing project (resolved via `ProjectService.getProjectForUri`).
    - Mapped outcomes to test controller results (`run.passed`, `run.failed`, `run.skipped`).
  - **DebugService JVM debug session management**:
    - Added workspace trust verification.
    - Validated project is a Grails application.
    - Verified presence of Java debugger extension (`vscjava.vscode-java-debug` or `redhat.java`) and reported unsupported configuration when absent.
    - Dynamic socket polling to localhost:5005 with timeout and cancellation token instead of hardcoded 8s sleep.
    - Hooked `onDidTerminateDebugSession` to cancel underlying Gradle execution and clean up resources.
  - **Project Resolution & UseCases**:
    - Added `getProjectForUri` and `resolveTargetProject` in `ProjectService`.
    - Created application layer UseCases: `RunGrailsAppUseCase`, `DebugGrailsAppUseCase`, `TestGrailsAppUseCase`, `BuildGrailsProjectUseCase`, `CleanGrailsProjectUseCase`.
    - Delegated task command handlers to UseCases with active editor project resolution.
    - Upgraded `LegacyCommands` to use `GradleService` and mapped legacy targets.
  - **Unit testing & verification**:
    - Created `runDebugTestWorkflows.unit.test.ts` with 7 comprehensive subtests verifying project resolution, test discovery/execution agreement, cancellation/disposal, actionable errors, workspace trust, debug configuration, and UseCases.
