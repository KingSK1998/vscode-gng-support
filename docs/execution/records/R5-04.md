# Task record: R5-04 — Present human and agent change reviews

## Task and session

- Task ID, session date, agent/coordinator and scope of this slice: R5-04, 2026-10-12, Antigravity. Scope: Present the same change review to humans and agents. Connect proposed/applied edits, source evidence, change impact, checks actually run, and unchecked assumptions using a unified change/input identity; invalidate stale review/check claims when buffer or dependency generations advance; maintain visibility of partial application and failed checks with actionable recovery; provide accessible, theme-aware navigation for both editor webview/UI and tool consumers (`INV-TOOL-001/002/003`, `INV-DISC-003`).
- Branch/commit and relevant pre-existing dirty files: `develop`.
- Acceptance card/specs read: `docs/execution/task-specifications.md#r5-04`, `docs/specs/agent-tools.md`, `docs/specs/ide-workflows.md`, `docs/invariants.md`.

## Evidence brief before implementation

- Current behavior:
  - R5-01 implemented change impact analysis (`grails.analysis.changeImpact`).
  - R5-02 implemented version-aware rename previews and apply (`grails.refactor.preview`, `grails.refactor.apply`).
  - R5-03 implemented scoped compile and test checks (`grails.checks.run`).
  - Prior to R5-04, these operations produced separate disparate records with independent lifecycles without a unified review model connecting edits, impact ripples, executed test checks, and unchecked assumptions under a single stable `changeId` and `analysisRevision`.
  - When editor buffers were modified after a check was run or preview generated, agents or users had no mechanism to detect buffer generation advancement and invalidate obsolete claims.
  - No accessible editor view rendered this comprehensive review with keyboard accessibility, high contrast/theme compliance, and honest safety verdicts.
- Failure/missing behavior and smallest reproducer:
  - Proposing an edit and running a narrow test could lead an agent to claim the whole project is safe based merely on prose generation, violating `INV-TOOL-002`.
  - An unsaved buffer change bumping document version did not invalidate prior review claims unless tracked under a unified review identity.
- Relevant invariant IDs and affected owner/reader/cache boundaries:
  - `INV-TOOL-001`: Change review outputs identify exact input state (`analysisRevision: rev:<ver>:dep:<rev>`, `changeId`).
  - `INV-TOOL-002`: Previews/checks/application have explicit input identities, trust boundaries, and report honest results. No claimed approval merely from generated prose.
  - `INV-TOOL-003`: Bounded count/byte budgets, explicit limits, distinct statuses.
  - `INV-DISC-003`: Clearly distinguish verified compiler facts from dynamic unknowns and unchecked assumptions.

## Implementation decision

- Intended observable result; non-goals:
  - Server operation `grails.analysis.changeReview`:
    - Takes `ChangeReviewRequest` (`projectUri`, `changeId`, `edits`, `impact`, `checks`, `assumptions`).
    - Validates buffer versions and dependency generation against current snapshot.
    - Emits `ChangeReviewResponse` with unified `changeId`, `analysisRevision`, `freshness`, `status`, `safetyVerdict`, `editsSummary`, `impactSummary`, `checksSummary`, `uncheckedAssumptions`, and `recoveryActions`.
    - Detects stale buffer versions (`stale_buffer`), stale dependencies (`stale_dependency`), failed checks (`checks_failed`), or narrow test limitations and flags them honestly.
  - Client integration:
    - Protocol types in `client/src/shared/protocol/analysis.ts` and `shared/schemas/analysis-operations.json`.
    - `AnalysisToolService.getChangeReview` and `ChangeReviewUseCase`.
    - Editor command `grails.analysis.changeReview` and LM tool `grails_change_review`.
    - MCP tool `grails_change_review` in `GrailsMcpServer`.
    - Accessible presenter/webview: `ChangeReviewPresenter.ts` supporting screen-reader accessible markdown/HTML output, ARIA roles, focus preservation, keyboard navigation, CSP compliance, theme adaptability.
  - Tests:
    - Server `GrailsChangeReviewSpec.groovy` testing unified identity, buffer/dependency invalidation, and honest verdicts.
    - Client `changeReview.unit.test.ts` testing client service, LM tool, and presentation rendering.
